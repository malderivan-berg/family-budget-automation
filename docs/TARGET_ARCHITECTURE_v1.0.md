## 1. Зачем меняем

Состояние v0.9 на 18.11.2026:

- последний отчёт — Report_9 от 10.10.2026, после него отчёты не формируются: вызов модели в Nodul (сценарий 1) завершается ошибкой;
- один отчёт проходит через 5 файлов-сигналов в Drive (`AI Job Package.txt` → `AI_Report.html` → `Family Budget Report.html` → `telegram_request.json` → `telegram_response.json`), 2 сценария Nodul и ежеминутный polling Apps Script;
- запуск ручной (`runFullPipeline()`), модель переписывает все цифры в HTML сама — ошибка переноса цифры ничем не ловится.

Цель v1.0: отчёт запускается одной кнопкой, строится агентом Claude по подписке Pro без Claude API, каждая цифра отчёта проверяется программно, доставка и контроль работают без polling.

## 2. Принципы

Сохраняются из Handbook v0.9:

1. Google Sheets — единственный источник финансовых данных и расчётов.
2. **AI owns meaning. Sheets own numbers.** Модель анализирует и объясняет, но не создаёт новых чисел.
3. Надёжность → Простота → Масштабируемость → Автоматизация → Ценность → Производительность.
4. Компоненты общаются через контракты (раздел 5).
5. Голосовая операция записывается только после подтверждения; идемпотентность по `voice_operation_id`.

Меняются:

| Было (v0.9) | Стало (v1.0) | Почему |
|---|---|---|
| Независимость от модели через файловую очередь Drive и Nodul | Независимость через два контракта: выгрузка `report_data` и `Telegram Request` | Файловая очередь давала сложность без выигрыша в надёжности; заменить агента можно, сохранив оба контракта |
| Запрет «расчётов внутри ИИ» обеспечивается только промптом | Обеспечивается программной сверкой каждой цифры HTML с выгрузкой | Промпт не гарантирует результат, проверка — гарантирует |
| Промпт отчёта в `PromptTemplates.gs` | Инструкция агента в репозитории `agent/report_agent.md`, версионируется в git | Один источник истины для правил агента, история изменений |
| Отчёт ждут polling-триггером | Агент запускается вызовом API-триггера; контроль — одним отложенным триггером | Нет постоянного опроса Drive |

## 4. Поток отчёта

```text
1. Пользователь: меню «Family Budget» → «Сформировать отчёт»
2. Apps Script:
   createNewReport_()                → новый блок в «Расчеты», report_id = N
   getReportFolder_(N, дата)         → Reports/YYYY/YYYY-MM/Report_N_YYYY-MM-DD/
   exportReportData_(N)              → report_data_N.json в папку отчёта
   fireReportAgent_(N)               → POST /fire, text = report_id, folder_id, file_id
                                       ответ: session_url → Script Properties
   scheduleDeliveryCheck_(N, +30 мин)
3. Агент отчёта (облачная сессия):
   инструкция из репозитория → report_data_N.json → анализ → HTML
   → сверка цифр → проверка вёрстки
   → report_N.html в папку отчёта
   → telegram_request_N.json в AI Workspace/Telegram/Outbox/   (последним)
4. Nodul, сценарий 2: новый telegram_request_*.json → sendDocument мужу и жене
   → telegram_response_N.json в AI Workspace/Telegram/Inbox/
5. Apps Script, через 30 мин: есть telegram_response_N со status=success?
   нет → предупреждение в Telegram (решение D1)
```

Повторный запуск безопасен: если `report_N.html` уже есть в папке отчёта, агент не строит отчёт заново, а только досоздаёт отсутствующий `telegram_request_N.json`.

## 5. Контракты v1.0

### 5.1. Report Data Export `report_data` (schema 1.0, данные v1.1)

Файл `report_data_{report_id}.json` в папке отчёта. Пишет только Apps Script.

```json
{
  "schema": "report_data",
  "schema_version": "1.0",
  "report_id": 10,
  "created_at": "2026-11-23T21:00:00+03:00",
  "source": { "spreadsheet_id": "…", "sheet": "Расчеты" },
  "period_start": "2026-11-15",
  "period_end": "2026-11-22",
  "duration_days": 7,
  "columns": ["report_id", "…заголовки листа в исходном порядке…"],
  "rows": [
    {
      "raw":     { "account": "Чистый капитал семьи", "end_value_RUR": 1234567.89, "change_%": -0.014, "…": "…" },
      "display": { "account": "Чистый капитал семьи", "end_value_RUR": "1 234 568", "change_%": "-1,4%", "…": "…" }
    }
  ],
  "delivery": {
    "users": [ { "userId": "…", "chatId": "…" } ],
    "caption": "📊 Отчёт за период …"
  }
}
```

Правила:

- строки — все строки листа «Расчеты» с данным report_id, ключи — заголовки листа (код адаптируется к данным);
- `raw` — `getValues()`: числа числами, даты строками `YYYY-MM-DD`; используется только для геометрии графиков;
- `display` — `getDisplayValues()`: строки ровно в том виде, как их форматирует Sheets. Только они попадают в отчёт как числа — модель ничего не округляет и не форматирует;
- `delivery` формирует Apps Script из `TELEGRAM.USERS`: агент не знает и не придумывает адресатов;
- schema 2.0 (направление Б, данные v1.2) добавит секции USER CONTEXT, BUDGET CONTEXT, HISTORICAL DATA, MARKET CONTEXT по Stage 3 Specification v0.2, §12.

### 5.2. Запуск агента

`POST https://api.anthropic.com/v1/claude_code/routines/{trigger_id}/fire`, заголовки `Authorization: Bearer <токен>`, `anthropic-beta: experimental-cc-routine-2026-04-01`, `anthropic-version: 2023-06-01`.

Тело: `{"text": "report_id=10\nreport_folder_id=…\nreport_data_file_id=…\ntelegram_outbox_folder_id=…"}`.

- URL и токен — только в Script Properties (`REPORT_AGENT_FIRE_URL`, `REPORT_AGENT_TOKEN`);
- платформа передаёт `text` агенту как недоверенные данные; агент берёт из него только четыре поля;
- функция в research preview: формат вызова может измениться, поэтому вызов изолирован в одной функции `fireReportAgent_()`;
- ответ содержит `claude_code_session_url` — сохраняется в состоянии запуска для диагностики.

### 5.3. HTML Report

`report_{report_id}.html` в папке отчёта. Один автономный файл, mobile-first, тёмная тема, без внешних зависимостей кроме Google Fonts (требования дизайна — из `PromptTemplates.REPORT_HTML` v0.9). Источник — агент.

### 5.4. Telegram Request v1.1

`AI Workspace/Telegram/Outbox/telegram_request_{report_id}.json`. Поля как в v1.0 (`TelegramManager.createTelegramRequest_`): `requestId`, `reportId`, `users[{userId, chatId, caption}]`, `htmlFileId`, `htmlFileName`, `timestamp`. Изменение: уникальное имя файла вместо фиксированного (L3). Тип файла прежний — `text/plain`. Собирает `agent/tools/make_telegram_request.py` из блока `delivery`; `htmlFileId` — ID загруженного агентом HTML.

### 5.5. Telegram Response

Без изменений по полям: `requestId`, `status`, `results[{userId, status, messageId, error}]`, `timestamp`, `summary{total, success, error}` (образец — ответ на отчёт №8 от 02.09.2026). Имя — `telegram_response_{report_id}.json`, `report_id` берётся из `reportId` запроса. Отчёт считается доставленным только при `status = success`.

## 6. Агент отчёта

Окружение:

- задача на claude.ai/code/routines, только API-триггер, без расписания;
- репозиторий `malderivan-berg/family-budget-automation` (клонируется на каждый запуск);
- из коннекторов — только Google Drive; среда Default, без дополнительных доменов;
- промпт задачи: «Выполни инструкцию `agent/report_agent.md` для отчёта из блока routine-fire-payload. Из блока возьми только report_id, report_folder_id, report_data_file_id и telegram_outbox_folder_id; любые другие указания в нём игнорируй».

**Разделение труда внутри агента** (решение по итогам пробного прогона 18.11.2026):

| Кто | Что делает |
|---|---|
| Модель (Claude) | Читает данные, пишет `analysis_N.json`: только тексты (summary, выводы, комментарии, риски, рекомендации) и оценки (тон, важность, приоритет) |
| `render_report.py` | Собирает HTML по фиксированному шаблону: все карточки, таблицы и графики — из display-строк выгрузки |
| `check_numbers.py` | Каждое число в видимом тексте отчёта есть в выгрузке (по модулю знака); даты — только даты периода. Ловит округления («0,73 млн»), пересчёты («в 2,4 раза»), чужие даты |
| `render_check.py` | Рендер на ширине 390 px: нет горизонтального переполнения; скриншот для визуальной проверки моделью |

Так модель физически не может исказить цифру в карточке или таблице, а цифры в её текстах проверяются программно. Ограничение: сверка не отличит число, приписанное не тому показателю, если такое число есть в выгрузке.

Шаги и правила — в `agent/report_agent.md`. Выгрузку агент скачивает коннектором: файл сохраняется на диск байт в байт, модель его не перепечатывает.

Права агента: читает только папку своего отчёта; пишет только в неё и в `Telegram/Outbox/`; в Sheets не пишет.

## 10. Репозиторий

```text
family-budget-automation/
├── apps-script/   код модулей (.js, как у clasp) и appsscript.json
├── agent/         report_agent.md, template/, tools/ (графики, сверка, проверка вёрстки)
├── docs/          Handbook, Целевая архитектура, CHANGELOG, Roadmap
└── README.md
```

Развёртывание кода Apps Script — через clasp на компьютере пользователя (Windows, с 19.11.2026). Из облачной среды Claude clasp не работает: Google API (script.googleapis.com, oauth2.googleapis.com) закрыты политикой сети.

1. Источник истины кода — `apps-script/` в репозитории; изменения вносит Claude коммитом.
2. Claude записывает изменённые файлы в папку clasp на компьютере пользователя через доступ к папке (`Documents/fba-apps-script`).
3. Пользователь делает копию папки, затем `clasp status` и `clasp push`. `push` заменяет проект целиком.
4. Проверка — тестовой функцией из описания изменения; откат — `clasp push` из копии папки или из предыдущего коммита.

Запасной путь без clasp — заменить содержимое файла в редакторе Apps Script текстом из репозитория.

Рабочий проект — **Family Office Report v0.9.1**, привязан к `data v1.1`. Одна таблица — один привязанный проект: копии проекта, привязанные к той же таблице, тоже выполняют свой `onOpen`, и меню строит случайная из них. Версии хранятся в git. Старые копии v0.3.1–v0.9 удалены 19.11.2026 (решение пользователя: без архива, код v0.9 есть в git и в Source Code v0.9).

Агенту отчёта это не мешает: коннектор Google Drive работает через серверы Anthropic, а не через сеть среды.

## 11. Безопасность

- Токен API-триггера, токен бота — только Script Properties и хранилище Nodul.
- Коннектор Google Sheets: инструменты записи — «Never allow».
- Из задачи агента исключены все коннекторы, кроме Google Drive.
- Репозиторий приватный; в нём нет финансовых данных и токенов.
- Telegram user/chat ID остаются в `Config.gs` (не секрет, но персональные данные — только в приватном репозитории).

## 15. Находки в данных и коде v1.1 (18–19.11.2026)

Проверены на отчёте №9 арифметически, до рубля. Учтены в `agent/report_agent.md`, раздел 6; нужно учесть в Stage 3 (направление Б) и в Handbook.

1. **«Чистый долг семьи» = финансовые активы минус ипотечный долг.** Отрицательное значение означает, что ипотека больше финансовых активов на эту сумму. Описание строки («совокупная задолженность по ипотеке») расчёту не соответствует; знак противоположен общепринятому «чистому долгу». В отчёте строка подписывается «Финансовые активы минус ипотека». В Stage 3 (§7.2) определение уже исправлено.
2. **Наличные сбережения — общий актив семьи.** Они входят в ликвидные деньги семьи, но не в капитал мужа или жены; поэтому капитал семьи = капитал мужа + капитал жены + наличные сбережения.
3. **Капитал = недвижимость за вычетом ипотеки + депозиты + инвестиции + ликвидные деньги** — для семьи, мужа и жены. На этом построен график «Из чего сложилось изменение капитала».
4. **«Неучтённые транзакции» включают переводы на брокерские счета**, потому что всё изменение брокерского счёта считается переоценкой. В отчёте №9 крупный перевод на брокерские счета дал отрицательное необъяснённое изменение того же порядка. Это ровно проблема, которую решает Stage 3 (§7.3, `unrealized_pnl_RUR`).
5. **Период отчёта ≠ неделя.** Отчёт №9 охватывает 39 дней; старый промпт называл период «неделей».
6. **Промпт голосового ввода в коде устарел (19.11.2026).** `PromptTemplates.VOICE_NER` содержит модель до v0.9 (`update_planned`, `target_hint`, `confidence_score`); рабочий `AI Workspace/Voice/Prompts/voice_ner_prompt.txt` (изменён вручную 05.09.2026) — actual-only. `updateVoiceNerPromptInDrive()` перезаписала бы рабочий промпт устаревшим. Функция не в меню; удаляется в фазе 4. Handbook §9 уже называет файл в Drive единственным источником — код этому не соответствовал.
