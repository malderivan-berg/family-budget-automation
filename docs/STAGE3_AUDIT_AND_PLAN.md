## 1. Итог

Работа в Google Sheets по Этапу 3 в основном сделана: справочник показателей, сверка капитала, месячный план и его исполнение, история за 84 дня, рыночный контекст. Формулы без ошибок, сверка капитала сходится до рубля. Переключиться на v1.2 мешают пять вещей: жёстко заданные диапазоны в формулах, отсутствие данных для неучтённого потока, отставание данных от рабочей таблицы, отсутствие механизма создания нового отчёта в формате v1.2 и отсутствие выгрузки и шаблона агента под новые листы.

## 4. Находки

**F1. Жёстко заданные диапазоны (надёжность, L1).** Формулы перестанут видеть новые строки без всякой ошибки:

| Где | Диапазон | Когда сломается |
|---|---|---|
| История | `$B$2:$B$329` и др. (собственный лист) | Со следующего отчёта: новые строки не попадут в статистику |
| Сверка капитала, Исполнение плана, Расчеты, Рыночный контекст | `'Сверка капитала'!…$500`, `'Расчеты'!…$500` | «Расчеты» — около 41 строки на отчёт: примерно на 13-м отчёте |
| Сверка капитала | `'Остатки'!…$1000` | Около 36 строк на период: примерно на 27-м периоде |
| Финансовый план (сводка PLAN VIEW) | `$F$2:$F$96` и др. | Сразу: план на новые месяцы ниже строки 96 не попадёт в сводку |

Исправление — открытые диапазоны (`$B$2:$B`) через «Найти и заменить» в формулах (раздел 6, шаг 5.1): `$329` (9 184 вхождения), `$500` (390), `$1000` (1 272), `$96` (648). Проверено по выгрузке: каждое вхождение — конец диапазона, одиночных ссылок на эти строки нет. Диапазоны `…$9999` («Рынки», «Остатки») и `…$999` («Контекст отчетов») оставить: их хватит на годы.

**F2. Нет данных для неучтённого потока (E, G).** Без нереализованной прибыли брокерских счетов на начало и конец периода сверка не отделяет переоценку от переводов, и неучтённый поток не считается. Требуется процесс ввода: вместе с остатками каждого периода — строка `value_role = unrealized_pnl` по каждому брокерскому счёту (из приложения брокера). Исторические значения не восстанавливаются (§17 спецификации).

**F3. Контекст пользователя не реализован (N).** Нужен поток Telegram → Nodul → Drive → Apps Script → «Контекст отчетов». Не блокирует переключение: агент обрабатывает пустой контекст.

**F4. Данные v1.2 отстали от рабочей таблицы.** v1.2: остатки по 01.09.2026, Календарь по 08.09.2026. Рабочая v1.1: отчёты до №10, 64 операции Календаря после 08.09.2026. Структура «Остатков» различается (в v1.2 добавлены `account_key`, `value_native`, `currency`, `fx_rate_RUR`, `value_role`, ссылки). Нужна функция переноса с таблицей соответствия счетов `account_name → account_key`.

**F5. Нет создания отчёта в формате v1.2.** Новый отчёт — это блок строк в пяти листах: Расчеты (~41), История (~41, ссылается на строки «Расчетов»), Сверка капитала (3), Исполнение плана (по владельцам и статьям), Рыночный контекст (по рыночным рядам). В v0.9 копируется последний блок одного листа; для v1.2 то же действие нужно в пяти листах.

**F6. Внутренние переводы (D).** Правило «переводы между своими счетами не вносятся в Календарь» записать в Handbook и в инструкцию голосового ввода.

**F7. Шаблон агента привязан к v1.1.** `render_report.py` и карта показателей v1.1 опираются на строки и названия счетов v1.1. В v1.2 — `metric_key` и справочник «Показатели»: карту показателей заменяет сам справочник (источник истины — Sheets).

## 5. Как Этап 3 ложится на архитектуру v1.0

| Подэтап спецификации | В v1.0 |
|---|---|
| 3.0–3.5 (данные и расчёты) | Google Sheets `data v1.2` — без изменений принципа |
| 3.6 AI Job Package | `report_data` schema 2.0: строки отчёта из «Расчетов» (длинный формат), «Сверки капитала», «Исполнения плана», «Истории», «Рыночного контекста», «Контекста отчетов» по `report_id` + справочник «Показатели»; `raw` + `display` как в 1.0 |
| 3.6 Правила AI | Инструкция агента v2.0: те же правила + бюджет, история, рынок, контекст, качество (`quality_status`) |
| 3.7 Report UX | Шаблон v2.0: блоки «Исполнение плана» (прогресс), «Сверка капитала», «На фоне 84 дней», «Рынок», «Пояснения» |
| 3.8 Регрессия | Пилот на v1.2 в тестовом режиме + сравнение ключевых показателей v1.1 и v1.2 по отчётам 9–10 |

Принцип «числа — только из Sheets» и сверка чисел не меняются. Выгрузка адаптируется к данным: листы и колонки читаются по заголовкам.

**Версия.** `report_data` — официальный контракт; его изменение по §23 Handbook — Major: выпуск Этапа 3 — **v2.0**.
